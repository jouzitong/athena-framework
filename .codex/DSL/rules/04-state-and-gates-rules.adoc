= Codex DSL 状态机与门禁规范（State and Gates Rules）
:toc: left
:toclevels: 2
:sectnums:
:version: 1.0

== 规范目标

统一 Task/Sub Task 生命周期状态与阶段门禁，避免不同规则文件出现冲突定义。

== 状态定义（统一）

- `TODO`：已定义，未满足执行前置条件。
- `READY`：满足执行前置条件，可进入执行。
- `DOING`：执行中。
- `DONE`：完成且通过裁决。
- `BLOCKED`：被阻塞，需外部条件解除后再恢复。

== 允许流转

- `TODO -> READY -> DOING -> DONE`
- `READY -> BLOCKED`
- `DOING -> BLOCKED`
- `BLOCKED -> READY`

== 禁止流转

- `TODO -> DOING`（禁止跳过 READY）
- `READY -> DONE`（禁止跳过执行与验证）
- `BLOCKED -> DONE`（必须先恢复 READY 并完成执行）
- 任意状态直接回退到 `TODO`（除 DSL 升级任务显式允许）

== 执行门禁（Sub Task）

子任务进入 `READY` 必须满足：

- 依赖子任务全部为 `DONE`（若存在 depends_on）
- 执行范围与目标已明确
- 对应规则和流程可定位（`rules/*` + `flows/*`）

子任务进入 `DONE` 必须满足：

- 已产生 Execution Log（包含 5 个步骤）
- Validate 显式结论为“通过”
- `sub_task.completion.success` 条件满足

== 执行门禁（Task）

任务进入 `DONE` 必须满足：

- 全部必须完成的 Sub Task 为 `DONE`
- `task.completion.success` 条件满足
- 不存在未裁决的高风险阻塞项

任务进入 `BLOCKED` 的典型触发：

- 核心依赖不可用
- 关键权限/环境缺失
- 需求目标不可裁决

== 裁决优先级

当多个文档对状态/门禁有冲突时，优先级如下：

1. 本文件（统一状态机与门禁）
2. `rules/01-task-rules.adoc`
3. `flows/task-execution-flow.adoc`
