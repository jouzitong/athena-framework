:doctype: book

== 规范说明

本文档是任务相关定义的唯一权威文件，统一融合以下内容：

- 需求任务/开发任务定义
- 任务拆分与挂接关系
- 开发任务输入输出与验收
- 状态机与执行约束摘要

== 基本原则

- 一个需求对应一个需求任务（Requirement Task）。
- 一个需求任务可挂接多个开发任务（Development Task）。
- 开发任务是最小执行单元。
- 开发任务完成是需求任务完成的必要条件。
- 仅 `READY` 状态任务允许进入执行。

== 核心语义

=== 需求任务（Requirement Task）

需求任务核心职责：

- 描述需求入口信息（背景、目标、范围）
- 提供开发所需上下文（依赖、约束、风险）
- 定义整体验收标准与失败判定

需求任务不承载具体实现步骤。

=== 开发任务（Development Task）

开发任务核心职责：

- 定义具体工作内容
- 定义输入与输出
- 定义通过/失败验收条件
- 提供执行证据与结果

典型开发任务可覆盖：原型设计、开发实现、系统测试、文档更新。

=== 完成判定关系

- 开发任务是最小裁决单元。
- 所有必须完成的开发任务达到 `DONE`，且满足 `task.completion.success`，需求任务才可判定 `DONE`。

== Task 文件结构

[source,text]
----
Task File（需求任务）
├─ Task Overview
├─ Task Meta
├─ Task Scope
├─ Risks & Notes
├─ Task Completion Policy
└─ Development Task Blocks（1..n）
----

== 需求任务定义规则

=== Task Overview

必须包含：

- 需求背景与目标
- 任务拆分方式
- 开发任务挂接关系
- 需求任务完成/失败判定逻辑

=== Task Meta

必须字段：

- `task.id`
- `task.name`
- `task.type`
- `task.version`
- `task.status`
- `task.objective`

约束：

- `task.id` 全局唯一
- `task.objective` 仅描述结果，不描述实现步骤

=== Task Scope

必须字段：

- `task.scope.modules`
- `task.scope.excludes`

约束：

- 范围与排除必须可判定

=== Task Completion Policy

必须字段：

- `task.completion.success`
- `task.completion.failure`

约束：

- 需求任务成功条件必须与开发任务结果、验证证据相关联

== 开发任务定义规则

=== 开发任务最小契约

每个开发任务必须定义：

- 工作目标（做什么）
- 输入（依赖什么）
- 输出（交付什么）
- 验收（如何通过/失败）

=== Development Task Blocks

[source,text]
----
Development Task Blocks
├─ Development Task Overview
├─ Development Task Meta
├─ Development Task Input
├─ Development Task Output
├─ Development Task Completion Policy
├─ Risks & Notes
└─ Execute Report
----

=== Development Task Meta

必须字段：

- `dev_task.id`
- `dev_task.name`
- `dev_task.type`
- `dev_task.status`
- `dev_task.objective`
- `dev_task.depends_on`（无依赖可写 `无`）

约束：

- `dev_task.id` 在所属需求任务内唯一
- `dev_task.depends_on` 必须可解析且无循环依赖

=== Development Task Input

建议至少包含：

- 前置开发任务产物
- 外部依赖（接口/配置/权限）
- 必需资源与边界条件

=== Development Task Output

建议至少包含：

- 交付结果（代码、文档、测试报告等）
- 可验证证据（日志、测试结果、评审结论）

=== Development Task Completion Policy

必须字段：

- `dev_task.completion.success`
- `dev_task.completion.failure`

约束：

- 成功条件必须可验证
- 失败条件必须具备明确触发器

=== Execute Report

必须包含：

- 执行摘要
- 关键变更
- 验证与证据
- 问题与结论

== 状态定义

统一状态集：

- `TODO`：已定义，未满足执行前置条件。
- `READY`：满足执行前置条件，可进入执行。
- `DOING`：正在执行中。
- `DONE`：完成并通过裁决（终态）。
- `BLOCKED`：被阻塞，需外部条件解除。
- `CANCELLED`：被主动终止，不再继续（终态）。

== 状态机流转规则

=== 文字图（直观视图）

[source,text]
----
                     +-------------------+
                     |    CANCELLED      |
                     |     (终态)        |
                     +-------------------+
                      ^        ^      ^
                      |        |      |
                  TODO|    READY|  DOING/BLOCKED
                      |        |      |

 +--------+      +--------+      +--------+      +--------+
 |  TODO  | ---> | READY  | ---> | DOING  | ---> |  DONE  |
 +--------+      +--------+      +--------+      +--------+
                   |   ^            |
                   |   |            |
                   v   |            v
                +-----------+ <-----+
                |  BLOCKED  |
                +-----------+
----

=== 流转说明

- 主执行路径：`TODO -> READY -> DOING -> DONE`
- 阻塞恢复路径：`READY -> BLOCKED`、`DOING -> BLOCKED`、`BLOCKED -> READY`
- 取消路径：`TODO/READY/DOING/BLOCKED -> CANCELLED`

=== 禁止流转

- `TODO -> DOING`（禁止跳过准备）
- `READY -> DONE`（禁止跳过执行与验证）
- `BLOCKED -> DONE`（未解除阻塞不得完成）
- `DONE -> CANCELLED`（完成后不可取消）
- `CANCELLED -> *`（默认不可恢复；如需恢复应新建任务）

=== CANCELLED 记录要求

当任务进入 `CANCELLED` 时，必须记录：

- 取消原因
- 已完成部分
- 收尾动作（如有）

== 拆分与挂接规则

- 开发任务按“可独立执行、可独立裁决”拆分。
- 开发任务之间必须显式声明依赖。
- 禁止过度拆分或不可执行拆分。
- 拆分结果必须覆盖需求目标达成所需链路（如原型/开发/测试/文档）。

== 执行约束摘要

- 进入前置：任务/开发任务处于 `READY`，依赖已满足。
- 执行顺序：`ANALYZE -> PLAN -> EXECUTE -> VALIDATE -> REPORT`。
- 执行边界：`EXECUTE` 仅允许修改 `PLAN` 声明文件。
- 校验要求：`VALIDATE` 必须显式通过/不通过。
- 报告要求：`REPORT` 必须包含证据与风险。

== 常见错误

- 把实现步骤写进需求任务 Objective
- 开发任务只有目标，没有输入输出
- 开发任务验收条件不可验证
- 开发任务依赖缺失或循环依赖
- 需求任务完成条件未与开发任务结果关联
