= Codex DSL 单一真相源映射规范（SSOT Rules）
:toc: left
:toclevels: 2
:sectnums:
:version: 1.0

== 规范目标

建立 DSL 的单一真相源（SSOT）映射，避免同一规则在 `rules` 与 `flows` 中重复维护并发生漂移。

== SSOT 映射原则

- `flows/*`：负责“步骤顺序与流程行为”。
- `rules/*`：负责“字段约束、状态机、门禁与裁决标准”。
- `template/*`：负责“输出骨架”，不得创造新规则。
- 执行层：负责“执行方法”，不得覆盖 DSL 规则。

== 关键主题归属表

[cols="1,2,2"]
|===
|主题 |唯一权威文件（SSOT） |其他文件处理方式

|执行步骤顺序（ANALYZE/PLAN/EXECUTE/VALIDATE/REPORT）
|`flows/task-execution-flow.adoc`
|`rules` 中仅可摘要引用，不可全文复制

|标准开发阶段顺序（INTAKE 到 DELIVERY_DECISION）
|`flows/standard-dev-flow.adoc`
|阶段门禁与裁决写在 `rules/06-standard-dev-flow-rules.adoc`，执行细节在 DSL 外部执行层维护

|Task/Sub Task 字段结构
|`rules/01-task-rules.adoc`
|`template` 与执行层产物必须引用并对齐

|日志字段与日志步骤
|`rules/02-logs-rules.adoc`
|`template/logs/*` 只做占位，不扩展新字段语义

|状态机与门禁
|`rules/04-state-and-gates-rules.adoc`
|其他规则文件如有冲突，按本文件裁决

|核心对象模型
|`rules/04-core-model-rules.adoc`
|其他文档引用，不重复定义对象最小契约
|===

== 防重复维护规则

- 若内容已在 SSOT 文件完整定义，其他文件只允许保留：
  - 文件引用
  - 1~3 条必要摘要
  - 与当前主题直接相关的补充约束
- 禁止在不同文件维护同一字段含义的不同版本。

== 变更流程要求

当修改 SSOT 主题时，必须按顺序执行：

1. 修改对应 SSOT 文件
2. 同步调整引用文件（rules/flows/template）
3. 在 `.codex/DSL/updates/README.adoc` 与 `updates/logs/*` 记录变更
