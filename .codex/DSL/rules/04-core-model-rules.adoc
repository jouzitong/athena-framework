= Codex DSL 核心对象模型规范（Core Model Rules）
:toc: left
:toclevels: 2
:sectnums:
:version: 1.0

== 规范目标

本规范定义 DSL 的三个核心对象及其最小契约，作为 Task 执行与裁决的统一语义基线。

核心对象：

- Task
- Sub Task
- Execution Log

== 对象一：Task

=== 必填字段

- `task.id`
- `task.name`
- `task.type`
- `task.version`
- `task.status`
- `task.objective`
- `task.scope.modules`
- `task.completion.success`
- `task.completion.failure`

=== 约束

- `task.id` 全局唯一。
- `task.status` 必须遵循状态机规范（见 `rules/04-state-and-gates-rules.adoc`）。
- `task.objective` 只描述结果，不描述实现步骤。
- `task.completion.*` 必须可验证、可裁决。

== 对象二：Sub Task

=== 必填字段

- `sub_task.id`
- `sub_task.name`
- `sub_task.type`
- `sub_task.status`
- `sub_task.objective`
- `sub_task.depends_on`（无依赖可显式写 `无`）
- `sub_task.completion.success`
- `sub_task.completion.failure`

=== 约束

- `sub_task.id` 在所属 Task 内唯一。
- 若 `sub_task.depends_on` 非空，被依赖项必须为 `DONE`，当前子任务才可进入 `READY`。
- 子任务完成判定以 `sub_task.completion.*` 与执行日志证据为准。

== 对象三：Execution Log

=== 必填字段

- `log.id`
- `task.id`
- `sub_task.id`
- `flow.id`
- `flow.version`
- `log.status`
- `log.created_at`
- `log.owner`

=== 必填步骤

- Step 1: Analyze
- Step 2: Plan
- Step 3: Execute
- Step 4: Validate
- Step 5: Report

=== 约束

- 日志必须与一次 Sub Task 执行过程一一对应。
- `Plan` 与 `Execute` 的文件清单必须可对照；若偏差，必须解释。
- `log.status=FINAL` 前必须完成 5 步记录。

== 对象关系与裁决

- Task 由一个或多个 Sub Task 组成。
- Task 是否 `DONE`，由其 `task.completion.success` 与 Sub Task 状态共同裁决。
- Sub Task 状态裁决必须有 Execution Log 作为证据。
